# 架构决策 - 专业术语库方案

**决策日期**：2026年04月11日

## 背景

当前语义搜索使用 BGE-M3 向量模型，存在专业术语匹配不准确的问题：
- 搜索英文缩写（如"PRD"）无法匹配中文全称（如"产品需求文档"）
- 用户需要知道多个同义词才能获得完整搜索结果
- 缺乏系统化的专业术语管理

这影响了搜索体验，特别是对产品经理、开发者等专业用户。

## 解决方案

### 核心方案
建立**专业术语库系统**，实现查询扩展和智能匹配：

```
用户搜索"PRD" 
  → 匹配术语库 
  → 扩展为 ["PRD", "产品需求文档", "需求文档", "PRD文档"]
  → 执行混合搜索
  → 返回综合结果
```

### 技术架构

**1. 数据库设计**
```sql
CREATE TABLE glossary (
    id INTEGER PRIMARY KEY,
    term VARCHAR(100) UNIQUE,           -- 术语名称
    category VARCHAR(50),                -- 分类
    synonyms TEXT NOT NULL,              -- 同义词（JSON）
    description TEXT,                    -- 描述
    examples TEXT,                       -- 使用示例
    is_enabled BOOLEAN DEFAULT 1,        -- 是否启用
    usage_count INTEGER DEFAULT 0,       -- 使用次数
    created_at DATETIME,
    updated_at DATETIME
);
```

**2. API设计**
- `GET /api/glossary/` - 获取术语列表
- `POST /api/glossary/` - 添加术语
- `PUT /api/glossary/{id}` - 更新术语
- `DELETE /api/glossary/{id}` - 删除术语
- `GET /api/glossary/search/{query}` - 搜索匹配术语

**3. 搜索集成**
在 `chunk_search_service.py` 中集成术语扩展：
```python
async def expand_query_with_glossary(query: str) -> List[str]:
    """使用术语库扩展查询"""
    matched_terms = await glossary_service.match_terms(query)
    expanded_queries = [query]
    for term in matched_terms:
        expanded_queries.extend(term.synonyms)
    return list(set(expanded_queries))
```

**4. 预置术语**
预置100+常用术语，覆盖以下分类：
- 产品类：PRD、MRD、BRD、MVP、OKR
- 技术类：API、SDK、REST、JSON、CLI
- 开发类：Git、CI/CD、Docker、K8s
- 设计类：UI、UX、Mockup、Wireframe
- 数据类：SQL、NoSQL、ETL、BI
- 运维类：SLA、SLO、MTTR、MTTF

### 用户交互

**搜索时**：
1. 自动匹配术语库
2. 显示匹配的术语和同义词
3. 用户选择是否启用扩展搜索
4. 返回综合结果

**管理时**：
1. 术语管理页面（增删改查）
2. 按分类浏览
3. 导入/导出功能
4. 使用统计和热门术语

## 影响

### 正面影响
✅ **搜索体验提升**：用户搜索"PRD"也能找到"产品需求文档"
✅ **专业性增强**：建立领域知识库，形成产品护城河
✅ **可维护性**：术语集中管理，易于更新和扩展
✅ **用户可控**：用户可选择是否使用扩展功能
✅ **数据洞察**：统计术语使用频率，优化产品方向

### 技术依赖
- 需要新增 `glossary` 数据库表
- 需要新增术语管理 API 端点
- 需要修改搜索服务集成术语扩展
- 需要新增前端术语管理页面
