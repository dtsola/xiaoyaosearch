# 架构决策 - 术语扩展并发搜索方案

**决策日期**：2026年04月12日

## 背景

当前术语扩展功能仅返回扩展信息给前端展示，但实际搜索仍使用原始查询词，没有充分利用术语库的同义词扩展能力。这导致用户配置术语库后，搜索召回率提升有限。同时，如果直接使用所有扩展词进行搜索，可能因扩展词过多导致性能问题和结果质量下降。

## 解决方案

采用**混合策略**（方案4），实现真正的术语扩展并发搜索：

### 核心实现

1. **并发搜索多个查询词**
   - 原始查询词 + 扩展查询词（最多N个）
   - 使用 `asyncio.gather()` 并发执行搜索
   - 每个查询词独立搜索，最后合并结果

2. **扩展词数量限制**
   - 默认值：3个（原始查询 + 2个扩展词）
   - 由前端配置界面控制，范围1-20
   - 扩展词优先级：原始查询 > 术语名称 > 同义词（按顺序）

3. **结果合并策略**
   - 按 `file_id` 去重
   - 同一文件取最高 `relevance_score`
   - 按聚合后的分数排序

### 技术实现

```python
async def search_with_expansion(query, search_type, limit, threshold, filters):
    # 1. 获取扩展词（限制数量）
    expanded_queries = [query]
    if self.enable_glossary_expansion:
        glossary_result = self.glossary_service.expand_query(query, ...)
        # 添加扩展词，最多 max_expansion_terms-1 个
        for term in glossary_result.expanded_queries[1:self.max_expansion_terms]:
            expanded_queries.append(term)

    # 2. 并发搜索所有查询词
    search_tasks = [
        self._chunk_search(q, search_type, limit, threshold, filters)
        for q in expanded_queries
    ]
    all_results = await asyncio.gather(*search_tasks)

    # 3. 合并并去重（按file_id）
    merged_results = self._merge_expansion_search_results(all_results)

    return merged_results
```

### 配置参数

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `max_expansion_terms` | 3 | 最大扩展词数量（包含原词），范围1-20 |
| `enable` | false | 是否启用术语扩展（前端控制） |
| `collection_ids` | null | 使用的术语库ID列表，null表示全部 |

**配置位置**：前端术语扩展设置界面

### 扩展词选择策略

```
原始查询: "API"
术语匹配:
  - 术语: "API", 同义词: ["应用程序接口", "接口", "Application Programming Interface"]

扩展词选择（限制3个）:
  1. "API" (原始查询)
  2. "API" (术语名称，如不同则添加)
  3. "应用程序接口" (同义词1)
```

## 影响

### 正面影响

1. **搜索召回率提升**：通过术语同义词扩展，可以找到更多相关文档（预计提升60%）
2. **用户体验改善**：配置术语库后能明显感受到搜索效果提升
3. **性能可控**：通过限制扩展词数量，避免过度搜索
4. **灵活可配置**：用户可在界面自定义扩展词数量

### 负面影响

1. **搜索延迟增加**：并发多个搜索会增加响应时间（预计增加 50-200ms）
2. **结果相关性可能下降**：扩展词过多可能引入不相关结果
3. **实现复杂度提升**：需要实现并发搜索和结果合并逻辑

### 依赖关系

1. **依赖现有服务**：`GlossaryService.expand_query()`
2. **前端兼容**：返回格式保持兼容，新增 `glossary_expansion.queries_used` 字段
3. **配置依赖**：依赖 `app_settings` 表存储配置

### 后续优化方向

1. **智能过滤**：根据查询词与扩展词的相似度动态调整数量
2. **性能监控**：添加搜索延迟和召回率统计
3. **缓存优化**：缓存常见查询的扩展结果
