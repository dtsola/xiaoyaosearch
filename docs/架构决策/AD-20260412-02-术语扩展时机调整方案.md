# 架构决策 - 术语扩展时机调整方案

**决策日期**：2026年04月12日

## 背景

当前术语扩展功能的触发时机在 **LLM 查询增强之后**，导致术语匹配失败：

**当前流程：**
```
用户输入："PRD"
  ↓
LLM 查询增强 → "PRD 产品需求文档 产品需求说明书 产品规格文档..."
  ↓
术语扩展：查询 "PRD 产品需求文档..." 是否匹配术语库
  ↓
术语库：term="PRD", synonyms=["产品需求文档", "产品需求", "需求文档"]
  ↓
匹配逻辑：term.contains(query) → "PRD".contains("PRD 产品需求文档...") = False
  ↓
结果：matched_terms=0 ❌
```

**问题根源：**
- LLM 扩展后的查询词是长文本
- 术语匹配逻辑使用 `term.contains(query)` 检查"术语是否包含查询词"
- 长查询词无法被短术语匹配

## 解决方案

采用**方案2：调整术语扩展时机**，将术语扩展移到 **LLM 查询增强之前**。

### 新流程

```
用户输入："PRD"
  ↓
【第一步】术语扩展：查询 "PRD" 是否匹配术语库
  ↓
术语库匹配：term="PRD" → 匹配成功！
  ↓
返回扩展词：["PRD", "产品需求文档", "产品需求", "需求文档"]
  ↓
【第二步】LLM 查询增强：对原词 "PRD" 进行扩展
  ↓
LLM 返回："PRD 产品需求文档 产品需求说明书..."
  ↓
【第三步】合并去重
  ↓
最终查询词列表：["PRD", "产品需求文档", "产品需求", "需求文档", "产品需求说明书", ...]
  ↓
【第四步】并发搜索所有查询词
```

### 技术实现

**修改位置：** `backend/app/api/search.py`

**当前代码顺序：**
```python
# 1. LLM 查询增强
enhanced_query = await query_enhancer.enhance_query(request.query)

# 2. 执行搜索（包含术语扩展）
search_result_data = await search_service.search(enhanced_query)
```

**修改后顺序：**
```python
# 1. 术语扩展（在 LLM 之前）
original_query = request.query
glossary_expansion_result = None

if search_service.enable_glossary_expansion:
    glossary_expansion_result = search_service.glossary_service.expand_query(
        original_query,
        search_service.glossary_collection_ids
    )

# 2. LLM 查询增强（基于原始输入）
enhanced_query = original_query
if is_text_input(request.input_type):
    enhancement_result = await query_enhancer.enhance_query(original_query)
    enhanced_query = enhancement_result.get('expanded_query', original_query)

# 3. 合并扩展词并去重
all_queries = [original_query]

# 添加术语库扩展词
if glossary_expansion_result and glossary_expansion_result.matched_terms:
    all_queries.extend(glossary_expansion_result.expanded_queries)

# 添加 LLM 扩展词
llm_expanded_words = enhanced_query.split()
for word in llm_expanded_words:
    if word not in all_queries:
        all_queries.append(word)

# 去重
all_queries = list(set(all_queries))

# 4. 并发搜索所有查询词
search_result_data = await search_service.search_with_expansion(
    original_query,
    all_queries,
    search_type=request.search_type,
    limit=request.limit,
    filters=filters
)
```

### 新增 API 方法

在 `ChunkSearchService` 中添加新方法 `search_with_expansion()`：

```python
async def search_with_expansion(
    self,
    original_query: str,
    expanded_queries: List[str],
    search_type: SearchType,
    limit: int,
    threshold: float,
    filters: Optional[Dict[str, Any]] = None
) -> Dict[str, Any]:
    """使用预扩展的查询词列表进行并发搜索"""

    # 并发搜索所有查询词
    search_tasks = [
        self._chunk_search(q, search_type, limit, threshold, filters)
        for q in expanded_queries
    ]
    all_results = await asyncio.gather(*search_tasks)

    # 合并结果
    final_results = self._merge_expansion_search_results(all_results)

    return self._format_compatible_response(
        final_results,
        original_query,
        response_time,
        search_type,
        glossary_info,
        expanded_queries
    )
```

### 简化术语匹配逻辑

由于现在是对原始用户输入进行匹配，可以简化匹配逻辑：

```python
# 简化后的匹配逻辑（glossary_service.py）
def _match_terms(self, query: str, collection_ids: Optional[List[int]] = None):
    # 精确匹配或包含匹配
    db_query = db_query.filter(
        (GlossaryTermModel.term == query) |
        (GlossaryTermModel.term.contains(query)) |
        (GlossaryTermModel.synonyms.contains(f'"{query}"'))
    )
```

**原理解释：**
- `term == query`：精确匹配（"PRD" == "PRD"）
- `term.contains(query)`：术语包含查询词（用于"API"匹配"OpenAI API"）
- `synonyms.contains(f'"{query}"')`：同义词包含查询词（JSON 数组匹配）

## 影响

### 正面影响

1. **术语匹配准确率提升**
   - 基于原始用户输入匹配，不受 LLM 扩展干扰
   - 简短的用户输入更容易匹配到术语

2. **职责分离清晰**
   - **术语库**：专业领域的精确同义词扩展
   - **LLM**：通用查询的语义优化和扩展
   - 两者互补，不会冲突

3. **更好的用户体验**
   - 用户输入专业术语（"PRD"、"API"）→ 立即触发术语扩展
   - 用户输入通用查询（"怎么写产品文档"）→ LLM 优化
   - 两者结合，搜索召回率最大化

4. **性能优化**
   - 术语扩展在 LLM 调用之前执行
   - 可以基于术语扩展结果决定是否需要 LLM 扩展
   - 减少不必要的 LLM API 调用

### 负面影响

1. **实现复杂度增加**
   - 需要修改搜索 API 的调用顺序
   - 需要处理多个扩展源的合并去重
   - 需要新增 `search_with_expansion()` 方法

2. **可能的重复扩展**
   - 术语库和 LLM 可能扩展出相同的词
   - 需要有效的去重逻辑

3. **测试工作量增加**
   - 需要测试各种组合场景
   - 需要验证合并逻辑的正确性

### 依赖关系

1. **依赖现有服务**
   - `GlossaryService.expand_query()` - 术语扩展服务
   - `LLMQueryEnhancer.enhance_query()` - LLM 查询增强服务

2. **影响文件**
   - `backend/app/api/search.py` - 搜索 API（主要修改）
   - `backend/app/services/chunk_search_service.py` - 搜索服务（新增方法）
   - `backend/app/services/glossary_service.py` - 术语服务（简化匹配）

3. **向后兼容性**
   - API 接口保持不变
   - 返回格式保持兼容
   - 新增字段不影响现有功能

### 后续优化方向

1. **智能合并策略**
   - 根据查询类型自动选择扩展顺序
   - 专业术语优先术语库，通用查询优先 LLM

2. **缓存优化**
   - 缓存常见术语的扩展结果
   - 减少 LLM API 调用次数

3. **用户反馈学习**
   - 记录用户点击的搜索结果
   - 优化扩展词的权重和排序
