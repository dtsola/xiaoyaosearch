## 1. 特性概述

### 1.1 定位（一句话）
建立**多术语库集合系统**，支持用户自定义领域术语库（医疗、法律、IT等），在搜索时选择性使用，实现精准查询扩展。

### 1.2 背景与动机

**用户痛点**：
- 痛点1：搜索"PRD"无法返回"产品需求文档"相关内容，搜索"API"找不到"接口"相关文档
- 痛点2：不同行业/领域的术语容易混淆（医疗的"CT"和IT的"CT"完全不同）
- 痛点3：没有系统化的术语管理机制，无法按领域组织专业术语
- 痛点4：无法导入外部术语库（如行业标准术语），每次都要手动添加

**业务价值**：
- **领域隔离**：不同领域的术语独立管理，避免混淆（医疗术语库 vs IT术语库）
- **用户自定义**：用户可以创建自己的术语库，满足个性化需求
- **外部集成**：支持导入行业标准术语库（医疗、法律、金融等）
- **精准搜索**：用户可以选择只使用特定领域的术语库进行搜索扩展

**技术必要性**：
- 当前BGE-M3向量模型对英文缩写词的语义理解不足
- 需要支持多术语库并行管理和检索
- 需要灵活的术语库选择机制，避免不同领域术语干扰

### 1.3 目标用户

**主要用户**：
- **领域专家**：医生、律师、工程师等专业人员，需要搜索领域内专业术语
- **知识管理者**：需要维护团队/企业的专业术语库
- **普通用户**：需要快速导入外部术语库（如行业标准），提升搜索准确性

**使用场景**：
- 场景1：医生创建"医疗术语库"，包含CT、MRI、处方等术语，搜索时只使用医疗术语库
- 场景2：律师导入"法律术语库"CSV文件，包含合同、诉讼、法规等术语
- 场景3：开发者创建"IT术语库"，搜索时可以同时使用"IT术语库"+"产品术语库"
- 场景4：用户在搜索设置中选择默认使用的术语库组合

### 1.4 与主版本的关系

**依赖关系**：
- 依赖主PRD中的多模态搜索功能
- 依赖搜索服务（`chunk_search_service.py`）
- 依赖国际化系统（i18n）

**影响范围**：
- 搜索服务：新增术语扩展逻辑
- 数据库：新增glossary表
- API：新增术语管理端点
- 前端：新增术语管理页面

## 3. 用户故事（增量场景）

> **说明**：只记录新增场景或重大变更的场景

**场景1：医生创建医疗术语库**
- 作为医生
- 我想要创建一个"医疗术语库"
- 以便于搜索医学文档时能准确匹配专业术语

**验收标准**：
- [ ] 可以创建新的术语库，命名为"医疗术语库"
- [ ] 可以设置图标（如十字）和颜色（如红色）
- [ ] 可以添加医疗术语：CT（计算机断层扫描）、MRI（磁共振成像）等
- [ ] 在搜索设置中可以选择使用"医疗术语库"
- [ ] 搜索"CT"时只扩展为医疗相关的同义词

**场景2：律师导入法律术语库**
- 作为律师
- 我想要导入法律行业的标准术语库CSV文件
- 以便于快速建立完整的法律术语体系

**验收标准**：
- [ ] 支持上传CSV文件导入术语
- [ ] CSV格式：术语名称,同义词,描述（逗号分隔）
- [ ] 导入时显示进度和结果统计
- [ ] 导入失败的行显示详细错误信息
- [ ] 导入后可以查看和编辑术语

**场景3：开发者组合使用多个术语库**
- 作为开发者
- 我想要同时使用"IT术语库"和"产品术语库"
- 以便于搜索技术文档时能匹配到产品和技术的相关术语

**验收标准**：
- [ ] 在搜索设置中可以勾选多个术语库
- [ ] 支持设置默认术语库组合
- [ ] 搜索时自动使用选中的术语库组合
- [ ] 搜索结果显示使用了哪些术语库

**场景4：用户禁用某个术语库**
- 作为用户
- 我想要临时禁用某个术语库
- 以便于搜索时不受该术语库的干扰

**验收标准**：
- [ ] 可以快速启用/禁用术语库（开关按钮）
- [ ] 禁用的术语库不会在搜索扩展中使用
- [ ] 可以在术语库列表中查看启用状态

## 4. 核心流程（增量部分）

### 4.1 新增流程

**术语管理流程**：
```
用户访问术语管理页面
    ↓
查看术语列表（支持分类筛选、搜索）
    ↓
点击"添加术语"按钮
    ↓
填写术语信息：
  - 术语名称（如"PRD"）
  - 分类（如"产品"）
  - 同义词（如"产品需求文档"、"需求文档"、"PRD文档"）
  - 描述
  - 使用示例
    ↓
保存术语
    ↓
术语库更新完成
```

**术语扩展搜索流程**：
```
用户输入搜索查询（如"PRD"）
    ↓
系统自动匹配术语库
    ↓
找到匹配术语：PRD
    ↓
提取同义词：["PRD", "产品需求文档", "需求文档", "PRD文档"]
    ↓
显示术语提示（可选关闭）
    ↓
执行扩展搜索（同时搜索所有同义词）
    ↓
合并去重结果
    ↓
返回综合搜索结果
```

### 4.2 修改流程

```
原有搜索流程：
用户输入查询 → 直接搜索 → 返回结果

修改后流程：
用户输入查询 → 匹配术语库 → 扩展查询 → 搜索 → 返回结果
                  ↑
              变更点：新增术语匹配和查询扩展
```

#### 数据库变更

| 表名 | 变更类型 | 变更内容 | SQL示例 |
|-----|---------|---------|---------|
| glossary_collections | 新增表 | 术语库集合表 | 见下方SQL |
| glossary_terms | 新增表 | 术语表（关联到集合） | 见下方SQL |
| app_settings | 修改表 | 新增默认术语库配置 | ALTER TABLE |

```sql
-- 术语库集合表
CREATE TABLE glossary_collections (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name VARCHAR(100) NOT NULL UNIQUE,       -- 术语库名称（如"医疗术语库"）
    description TEXT,                         -- 术语库描述
    icon VARCHAR(50),                         -- 图标名称（如"medical"）
    color VARCHAR(20),                        -- 显示颜色（如"#FF5722"）
    is_enabled BOOLEAN DEFAULT 1,             -- 是否启用
    term_count INTEGER DEFAULT 0,             -- 术语数量（冗余字段）
    usage_count INTEGER DEFAULT 0,            -- 使用次数
    is_system BOOLEAN DEFAULT 0,              -- 是否为系统预置
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- 术语表
CREATE TABLE glossary_terms (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    collection_id INTEGER NOT NULL,           -- 关联的术语库ID
    term VARCHAR(100) NOT NULL,               -- 术语名称（如"PRD"）
    synonyms TEXT NOT NULL,                   -- 同义词（JSON数组）
    description TEXT,                         -- 术语描述
    examples TEXT,                            -- 使用示例（JSON数组）
    is_enabled BOOLEAN DEFAULT 1,             -- 是否启用
    usage_count INTEGER DEFAULT 0,            -- 使用次数
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (collection_id) REFERENCES glossary_collections(id) ON DELETE CASCADE
);

-- 索引
CREATE INDEX idx_gc_name ON glossary_collections(name);
CREATE INDEX idx_gc_enabled ON glossary_collections(is_enabled);
CREATE INDEX idx_gt_collection ON glossary_terms(collection_id);
CREATE INDEX idx_gt_term ON glossary_terms(term);
CREATE INDEX idx_gt_enabled ON glossary_terms(is_enabled);

-- 触发器：自动更新术语库的术语数量
CREATE TRIGGER update_collection_term_count
AFTER INSERT OR DELETE OR UPDATE ON glossary_terms
FOR EACH ROW
BEGIN
  UPDATE glossary_collections 
  SET term_count = (
    SELECT COUNT(*) FROM glossary_terms 
    WHERE collection_id = NEW.collection_id AND is_enabled = 1
  )
  WHERE id = NEW.collection_id;
END;
```

### 18.3 CSV导入格式说明

**文件格式**：CSV（逗号分隔值）
**编码**：UTF-8
**行分隔符**：\n 或 \r\n

#### CSV格式规范

```
术语名称,同义词,描述
CT,计算机断层扫描;CT扫描;Computed Tomography,X线计算机断层扫描
MRI,磁共振成像;MRI;Magnetic Resonance Imaging,磁共振成像
PRD,产品需求文档;PRD文档;Product Requirement Document,产品需求文档
```

#### 字段说明

| 字段 | 必填 | 格式 | 说明 |
|------|------|------|------|
| 术语名称 | 是 | 纯文本 | 术语的标准名称 |
| 同义词 | 是 | 分号分隔 | 多个同义词用分号(;)分隔 |
| 描述 | 否 | 纯文本 | 术语的详细解释 |

#### 注意事项

1. **同义词分隔符**：使用英文分号（;）分隔多个同义词
2. **空格处理**：同义词前后的空格会被自动去除
3. **重复检查**：导入时会检查术语名称是否重复
4. **错误处理**：某行导入失败不影响其他行
5. **最大长度**：术语名称≤100字符，同义词≤1000字符，描述≤2000字符

### 18.5 FAQ

**Q1：会有预置的术语库吗？**
A：会。系统首次启动时会自动初始化常用的术语库（如IT术语库、产品术语库、医疗术语库、法律术语库），具体包含哪些术语会在实施时确定。用户也可以创建自己的术语库或导入外部术语库。

**Q2：为什么要建立多个术语库，而不是一个统一的术语库？**
A：不同领域的术语可能有相同的缩写但含义完全不同。例如：
- 医疗的"CT"：计算机断层扫描
- 技术的"CT"：Computed Tomography（同词，但应用场景不同）
通过建立独立的术语库，可以避免术语混淆，用户可以根据当前搜索场景选择合适的术语库。

**Q3：如何同时使用多个术语库？**
A：在搜索设置中，可以勾选多个术语库。搜索时会从所有选中的术语库中匹配术语并扩展查询。例如，同时勾选"IT术语库"和"产品术语库"，搜索"API"时会同时扩展为"接口"和"应用程序接口"。

**Q4：可以导入外部术语库吗？**
A：可以！支持CSV格式导入。你可以从网上找到行业标准术语库（如医疗术语库、法律术语库），整理成CSV格式后导入。我们提供CSV模板和格式说明。

**Q5：术语库会影响搜索性能吗？**
A：影响很小（<20%）。我们通过以下方式优化：
1. 只从选中的术语库中匹配术语
2. 使用数据库索引加速查询
3. 缓存常用的术语匹配结果

**Q5：预置的术语库可以修改吗？**
A：可以。所有预置术语库都可以编辑、禁用或删除。建议禁用而不是删除，以便后续恢复。你也可以基于预置术语库创建自己的术语库。

**Q6：如何分享我的术语库？**
A：
1. 在术语库管理页面点击"导出"
2. 选择CSV格式
3. 将导出的文件分享给团队成员
4. 团队成员通过"导入"功能添加到自己的系统中

**Q7：术语库有数量限制吗？**
A：没有硬性限制。但为了性能考虑，建议：
- 单个术语库不超过1000个术语
- 同一用户创建的术语库不超过20个
- 总术语数量不超过5000个

**Q8：搜索时会使用哪个术语库？**
A：默认情况下，使用所有已启用的术语库。你可以在搜索设置中选择特定的术语库组合，系统会记住你的选择。
